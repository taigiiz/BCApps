# MN нутагшуулалтын багц (seed) — шинэ компанийн анхдагч тохиргоо

Энэ хавтас нь хууль журмын параметр (`legal_parameters.sql`) болон **Монголын нутагшуулалтын багцыг** агуулна. Багц нь шинэ компани үүсэхэд дансны төлөвлөгөө, posting group, НӨАТ, дугаарлалт, санхүүгийн жил, журнал, Маягт А-гийн тайлан, ТТ-03а, насжилт ба эрхийг **нэг функцийн дуудлагаар** үүсгэнэ.

```sql
-- tenant ба company (бас боломжтой бол company_setup: ТТД, vat_registered, district_code) үүссэний дараа:
SELECT platform.fn_provision_company_mn(:tenant_id, :company_id);         -- эхний санхүүгийн жил = байгаа эхний жил, эсвэл go_live_date-ийн он, эсвэл өнөөдрийн он (УБ)
SELECT platform.fn_provision_company_mn(:tenant_id, :company_id, 2027);   -- эхний санхүүгийн жилийг заах
```

Нэрийн эх сурвалж нь [`db/schema/*.sql`](../schema/) (D-K1). Шийдвэрүүд [DECISIONS.md](../../DECISIONS.md)-д нийцнэ. Дансны дугаарууд нь [01-requirements.md](../../01-requirements.md) §1.6-ийн жишээний дугаартай (1100, 1110, 1200, 1300, 1400, 1600, 1690, 2100, 2200, 2300, 3400, 3500, 5100, 6100, 7200, 8300, 8500, 8600) яг таарна.

> ⚠ **Дансны төлөвлөгөө нь санал болгож буй (proposed) загвар бөгөөд албан ёсны биш.** Сангийн сайдын 2017 оны 13-р тушаалаар 2000 оны 116-р тушаалын үлгэрчилсэн дансны төлөвлөгөө хүчингүй болсноос хойш энгийн аж ахуйн нэгжид заавал мөрдөх дансны төлөвлөгөө **байхгүй**. Компани бүр нягтлан бодох бүртгэлийн бодлогоороо өөрийн дансны төлөвлөгөөг баталдаг ([research/mn-accounting.md](../../research/mn-accounting.md) §4.1–4.2). Маягт А-гийн мөрийн кодууд мөн баталгаажаагүй (`rpt.statement_line.verified = false`).

## 1. Файлууд ба ачаалах дараалал

`db/apply.sh <url> --seed` нь эхлээд `legal_parameters.sql`-ийг, дараа нь `mn_*.sql`-ийг үсгийн дарааллаар ачаална. `--seed --test` нь нэмэлтээр [`tests/seed_checks.sql`](../tests/seed_checks.sql)-ийг ажиллуулна. Бүх файл idempotent (дахин ачаалж болно).

| Файл | Хамрах хүрээ | Юу үүсгэх |
|---|---|---|
| `legal_parameters.sql` | Глобал | `tax.tax_parameter`: огноотой хувь хэмжээ, босго, хугацаа (D-E7). **Өөрчлөхгүй**, эхэнд ачаална |

| `mn_30_posting.sql` | Компани | Gen. Bus./Prod. бүлэг, General Posting Setup (16, `*` мөртэй), харилцагч (3) / нийлүүлэгч (4, гааль орно) / банкны (7) posting group, төлбөрийн нөхцөл, валют, үндсэн хөрөнгө, хэмжих нэгж, бараа материал |

Компанийн функцүүд нь одоогийн контекстод (`app.tenant_id`, `app.company_id`) ажиллаж, **зөвхөн дутуу мөрийг нэмнэ** (`ON CONFLICT DO NOTHING`), засварласан мөрийг хэзээ ч дарж бичихгүй. Функц бүр нэмсэн мөрийн тоог буцаана. Шинээр нэмэх мөрийн ишлэл (Маягт А-гийн мөр, МГТ-ийн ангилал, анхдагч бүлэг, НӨАТ-ын болон борлуулалт/худалдан авалтын данс) олдохгүй бол функц **алдаа өгнө** (`55000`): дутуу ишлэлтэй мөрийг дараагийн дуудлага хэзээ ч засахгүй тул чимээгүй үүсгэхгүй.

## 2. `platform.fn_provision_company_mn` хэрхэн ажилладаг

1. Дуудагчийн контекст өөр тенантад холбогдсон бол татгалзана (`ERT01`, D-K6): функц хүсэлтийг гадны тенант руу хэзээ ч шилжүүлэхгүй (шинэ тенантын onboarding контекстгүй ажиллана). Дараа нь контекстыг `fn_set_context(tenant, company)`-оор тохируулж, компани тухайн тенантад байгааг шалгана (`ERT01`). Төгсгөлд нь дуудагчийн өмнөх контекстыг сэргээнэ.
2. Компани бүрд `pg_advisory_xact_lock` авна (зэрэг provisioning хийхгүй).
3. `platform.company_setup` байхгүй бол анхдагчаар үүсгэнэ: LCY **MNT**, нарийвчлал **0.01** (D-C2), НӨАТ төлөгч биш. ТТД, `vat_registered`, `city_tax_payer`, `district_code`-ийг **provisioning-ээс өмнө** бичвэл НӨАТ-ын матриц (D-E5), НХАТ, eBarimt-ийн мерчантын тохиргоо түүнд тааруулан үүснэ.
4. `gl.fn_initialize_company()` (хоосон dimension set 0, G/L setup).
5. Дараалал: НӨАТ-ын бүлэг → Gen. бүлэг → дансны төлөвлөгөө → VAT setup → General Posting Setup → банкны бүлэг → валют → ҮХ → бараа → дугаарлалт (эхний ба дараагийн жил) → шалтгааны код → санхүүгийн жил (эхний ба дараагийн, FR-PLT-003) → касс → журнал → G/L setup → төлбөрийн хэлбэр, загвар → модулийн тохиргоо → тайлан → ТТ-03а → насжилт → role.
6. `company.status = 'PROVISIONING'` байсан бол `ACTIVE` болгоно.
7. Хариу: `{"company_id", "fiscal_year", "rates_as_of", "inserted": {алхам: мөр}, "total_inserted"}`. Хоёр, гурав дахь дуудлага `total_inserted = 0` буцаана. Он заагаагүй давтан дуудлага компанийн **хамгийн эхний байгаа санхүүгийн жилд** тулгуурлана: дараа оны дуудлага эсвэл `go_live_date` өөрчлөгдсөн ч илүү жил, цувралын мөр нээгдэхгүй.

Хууль журмын хувь хэмжээ (`vat.standard_rate`, `city_tax.rate_ub`, `vat.return_due_day`) нь `tax.tax_parameter`-ээс эхний санхүүгийн жилийн эхэн ба өнөөдрийн аль хожуу огноогоор уншигдана. Параметр байхгүй эсвэл `verified` биш бол алдаа өгнө — код дотор хувь хэмжээ бичээгүй (D-E7).

Функц `SECURITY INVOKER` тул дуудагчийн RLS үйлчилнэ (`app_user` хангалттай). Бүх алхам дуудагчийн нэг DB transaction-д явагдана: алдаа гарвал юу ч хадгалагдахгүй, wizard-ийг дахин ажиллуулж болно (FR-PLT-003 AC2).

**Жил бүр:** хуулийн баримтын цуврал жил бүр шинээр эхэлдэг (`reset_yearly`, D-C7) тул тухайн жилийн мөр байхгүй бол дугаар олгохоос татгалзана (`ERN01`), үе байхгүй бол posting хийгдэхгүй (`ERP01`). Шинэ жилийн өмнө (жилийн хаалтын job) дараахыг дуудна:

```sql
SELECT platform.fn_mn_ensure_number_series(2028), gl.fn_mn_ensure_fiscal_year(2028);  -- idempotent
```

- **9900 "нэгдсэн данс" байхгүй:** D-D4-өөр орлого, зардлын дансыг 12-31-ний `is_closing` ваучераар шууд **3500**-д хаана. 01-01-нд 3500 → 3400 шилжүүлгийг санал болгоно.
- **Бүтэц:** `x000` = ангийн Begin-Total, `x999` = ангийн End-Total. Хөрөнгө ба өр төлбөрийн дотор эргэлтийн/эргэлтийн бус хэсэг нь Begin/End-Total хос (1001/1598, 1599/1998, 2001/2698, 2699/2998). **Heading нь бүлгийнхээ эхний дугаараас 1-ээр бага дугаартай** (жишээ: 1199 «Дансны авлага» → 1200-аас эхэлнэ), тиймээс дугаараар эрэмбэлэхэд бүлгийнхээ яг өмнө гарна.
- **Хяналтын данс** (`direct_posting = false`, FR-GL-003): касс, банк, хэтэвч (1100–1121), дансны авлага (1200, 1201, ажилтны 1360), орцын НӨАТ 1300, дансны өглөг (2100, 2101, ажилтны 2210), борлуулалтын НӨАТ 2300, урвуу тооцооны НӨАТ 2305, НХАТ 2320, гаалийн татвар ба импортын НӨАТ-ын өглөг 2365, бөөрөнхийлөлт 8290. Эдгээрт зөвхөн системийн бичилт орно. НӨАТ, НХАТ-ыг төлөхдөө тооцооны данс (2310, 2325) ашиглана: сарын хаалт 1300/2300-ийг 2310 руу хаагаад төлбөрийг 2310-оос хийнэ (BC VAT Settlement).
- **Бараа (14xx) ба үндсэн хөрөнгө (16xx, 17xx)** R1-д `direct_posting = true` (R1-д бараа, ҮХ-ийн модуль байхгүй, гараар бүртгэнэ). R2-т модулийг асаахдаа эдгээрийг `false` болгоно.
- **Анхдагч бүлэг:** орлого, зардал, ҮХ-ийн данс, мөн худалдаж авдаг бараа материалын данс (1400, 1410, 1440 → GOODS/VAT10; R1-д бараа материалыг худалдан авалтын нэхэмжлэхийн дансны мөрөөр капиталжуулна) бүр `gen_prod_posting_group` ба `vat_prod_posting_group`-тэй (жишээ: 5110 → SERVICES/VAT10, 7201 цалин → MISC/NOVAT, 8300 банкны шимтгэл → MISC/EXEMPT). Ингэснээр баримтын дансны мөр нэмэлт оролтгүйгээр posting setup-аа олно. `gen_posting_type` = NONE: журнал НӨАТ-ыг далдуур тооцохгүй, НӨАТ зөвхөн баримтаас (D-E4).
- Мөр бүр **Маягт А-гийн мөр** (балансын данс → СБТ, орлогын данс → ОДТ) ба **МГТ-ийн ангилалтай**. Хаалтын үед ангилалгүй данс байвал хаалт зогсоно (FR-GL-002); `seed_checks.sql` энэ нөхцлийг шалгана.

## 10. Хэрхэн өөрчлөх

1. **Өгөгдлийг засах:** тухайн файлын `VALUES (...)` мөрийг засаад `psql -f db/seed/mn_XX_*.sql` (эсвэл `apply.sh --seed`) ажиллуулна. Функцүүд `CREATE OR REPLACE` тул шинэ компани шинэ утгыг авна.

Байгаа мөрийн *утгыг* өөрчлөхийг (жишээ нь дансны нэр, хувь) компанийн өөрийн шийдвэрээр UI-аас, эсвэл тусдаа migration-оор хийнэ (ADR-0014) — seed хэзээ ч дарж бичихгүй.
3. **Данс нэмэх:** `mn_10_coa.sql`-д мөр нэмж, Маягт А-гийн мөр ба МГТ-ийн ангиллыг заана. Дугаар нь тайлангийн мөрийн хүрээнд (`mn_50_reports.sql`) таарч байх ёстой; `seed_checks.sql` зөрүүг илрүүлнэ.
4. **Хувь хэмжээ өөрчлөгдвөл** seed-ийг засахгүй: `legal_parameters.sql`-ийн эх өгөгдөлд (legal-parameters.md) шинэ `effective_from`-тэй мөр нэмнэ (D-E7). Posting engine огноогоор уншина; seed-ийн `vat_percent` нь зөвхөн анхны утга.

6. **Шинэ жил:** `platform.fn_mn_ensure_number_series(он)`, `gl.fn_mn_ensure_fiscal_year(он)`.
7. Өөрчлөлт бүрийн дараа: `db/apply.sh <scratch-db> --seed --test` (catalog, smoke, seed checks бүгд PASS байх ёстой).
