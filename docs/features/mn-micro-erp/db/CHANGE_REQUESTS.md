## 1. Хураангуй

**Арга.** (1) Давхардлыг арилгасан: ижил өөрчлөлтийг `write` ба `review` шатанд, эсвэл хоёр spec-д (жишээ нь 07 SCR-PUR-01 = 08 CR-TAX-02) давтан хүссэнийг нэг бүлэг болгосон; хяналтын шатны засвар (`MODIFIED`, `revised`, `extended`) анхныхаа хувилбарыг орлоно. (2) Бүлэг бүрд эхлээд одоогийн SQL-ийг шалгаж, шийдвэр гаргасан. (3) Хүлээн авсныг `schema/*.sql`-д (шаардлагатай бол seed-д) хэрэгжүүлж, конвенц (tenant/company, нийлмэл FK, FK индекс, COMMENT, FORCE RLS, аудит trigger, `ledger_guard`) ба тестийг шинэчилсэн. (4) Шинэ DB дээр `apply.sh --seed --test`-ээр давтан шалгасан.

Бусад давхардлыг (жишээ нь #128, #145, #159, #160) үндсэн бүлэгт нь нэгтгэсэн.

Тэмдэглэгээ: **Хүлээн авсан** — хүссэнээр хэрэгжүүлсэн; **Хүлээн авсан (өөрчлөлттэй)** — зорилгыг хангасан ч хэлбэрийг өөрчилсөн (шалтгааныг тэмдэглэлд); **Хэсэгчлэн** — нэг хэсгийг хэрэгжүүлж, үлдсэнийг татгалзсан эсвэл аль хэдийн байсан; **Аль хэдийн хангагдсан** — схемд байсан эсвэл өөр бүлгээр хэрэгжсэн давхардал; **Татгалзсан** — нөхцөл (нээлттэй асуулт) хангагдаагүй эсвэл хамрах хүрээнээс гадуур. "Эх spec" баганад spec-ийн дугаар, түүхий хүсэлтийн № (`w` = write, `r` = review шат).

## 3. Татгалзсан ба хэсэгчлэн татгалзсан хүсэлтүүд

- **Бүлэг 3** (#3, #21) — eBarimt `operation = 'MANUAL_VOID'`; B2B-д DELETE зөвшөөрөх: MANUAL_VOID хүлээн авсан: billIdSuffix-гүй, `replaces_document_id` + `inactive_ddtd` заавал, зөвхөн SUCCESS төлөвөөр INSERT (`910` guard). **B2B DELETE-ийг татгалзсан:** ITC баталгаажуулаагүй (нөхцөлт), D-J4 хэвээр — `CHECK (operation <> 'DELETE' OR ebarimt_type = 'B2C_RECEIPT')` өөрчлөгдөөгүй.
- **Бүлэг 13** (#13, #31) — PosAPI instance-ийн billIdSuffix counter (`posapi_instance_counter`): Нөхцөлт (ITC OQ-02 хариугүй). D-K4-ийн POS тус бүрийн reset-гүй counter хэвээр; хариу ирвэл дахин нээнэ.
- **Бүлэг 42** (#60) — R3: posted snapshot-ийн PII нэргүйжүүлэх SECURITY DEFINER функц: R3, хадгалалтын бодлого (13 §12) батлагдаагүй; posted баримт өөрчлөгдөхгүй (D-C4) зарчмаас үл хамаарах зөвшөөрөл шаардлагатай тул R3-ийн spec-тэй хамт дахин авч үзнэ.
- **Бүлэг 52** (#74) — Catalog: `gl.year.create`, `platform.webhook.manage`; `gl.journal_batch` RIMD, `fx.currency_exchange_rate` T_SETUP-д: ACTION хоёрыг нэмсэн (`ERP_PERIOD_CLOSE`, `ERP_SECURITY`). `ERP_JOURNALS_EDIT`-ийн `gl.journal_batch` RIMD ба `ERP_SETUP`-ийн `fx.currency_exchange_rate` **аль хэдийн seed-д байсан**.
- **Бүлэг 62** (#89) — `bank.cash_voucher_draft` (OQ-UI-22 тийм бол): Нөхцөлт; OQ-UI-22 хариугүй. Одоогийн журналын мөрөөр (`gl.journal_line`) МХ-1/МХ-2 ноорог хийгдэнэ.
- **Бүлэг 110** (#156) — `vendor_ledger_entry.cancelled` (OQ-PUR-07 тийм бол): Нөхцөлт; OQ-PUR-07 хариугүй. Цуцлалт нь буцаалтаар (`reversed`) — индексүүд `NOT reversed`-ээр шүүдэг.
- **Бүлэг 132** (#200) — Catalog: `fx.exch_rate_adjustment.post`; T_SETUP-д ханш, импортын формат, текстийн дүрэм: `fx.exch_rate_adjustment.post` (`ERP_PERIOD_CLOSE`), `bank.text_to_account_mapping` (`ERP_SETUP`) нэмсэн. `fx.currency_exchange_rate`, `bank.bank_statement_import_format`, `bank.statement.import`, `bank.reconciliation.post` **аль хэдийн seed-д байсан**.
- **Бүлэг 140** (#212, #225) — `gl.account_period_balance` projection (нөхцөлт): Нөхцөлт; гүйцэтгэлийн хэмжилт хийгдээгүй. `gl.v_gl_account_period_balance` view ба `ix_gl_entry__transaction INCLUDE` (#214) хангалттай; хэмжилтээр шаардлагатай бол нэмнэ.

Нөхцөлт ба R3-ийн хүсэлтүүдийг (бүлэг 13, 42, 62, 110, 140) холбогдох нээлттэй асуулт хаагдах эсвэл R3-ийн spec батлагдахад дахин нээнэ; [03-domain-model.md](../03-domain-model.md) §8 #7-д жагсаав.
