# Шийдвэрийн бүртгэл (Decision Register)

> Энэ файл нь бүх баримт бичиг, схем, тестийн **нэг эх сурвалж** юм. Судалгааны явцад гарсан ~95 нээлттэй асуултад
> анхдагч (default) шийдвэр гаргасан. Шийдвэр бүр "Эргэж харах нөхцөл"-тэй. Өөрчлөх бол энд засаж, холбогдох баримтуудыг шинэчилнэ.
> Огноо: 2026-10-06. Төлөв: **Батлагдсан анхдагч**. ⚠ тэмдэгтэй шийдвэрийг бизнес эзэн эсвэл нягтлан зөвлөх баталгаажуулах шаардлагатай.

## H. Хувилбарын агуулга

- **R1 (MVP):**
  - Tenant/company, хэрэглэгч, эрх (BC permission set загвар), компани тохируулах wizard + MN анхдагч тохиргоо.
  - CoA, ерөнхий журнал/posting/буцаалт, дугаарлалт, dimension (2 global).
  - НӨАТ (VAT10/0/EXEMPT, НӨАТ төлөгч бус горим), харилцагч/нийлүүлэгч, борлуулалт/худалдан авалтын нэхэмжлэх ба кредит нот, төлбөр ба тулгалт.
  - Касс/банк, хуулга импорт ба тулгалт.
  - eBarimt (B2C/B2B receipt, буцаалт, засвар, мониторинг), худалдан авалтын ДДТД.
  - Үе ба жилийн хаалт.
  - Тайлан: гүйлгээ баланс, ерөнхий дэвтэр, дансны хуулга, AR/AP насжилт, НӨАТ (ТТ-03а туслах), санхүүгийн тайлангийн Form A (СБТ, ОДТ, ӨӨТ, МГТ шууд арга) + Excel.
  - Аудитын лог, mn/en хэл.
- **R2:** валют ба Монголбанк, үндсэн хөрөнгө, бараа (дундаж), НХАТ, давтагдах журнал, dimension UI, нэхэмжлэх→төлбөрийн eBarimt урсгал (`*_INVOICE` + `invoiceId`), худалдан авалтын eBarimt татаж тулгах, цалингийн журнал импорт, хэрэглэгчийн posting цонх, засварлах боломжтой тайлан, netting.
- **R3:** захиалга, банкны API, QPay, approval, e-tax/e-balance шууд холболт, мобайл апп, FIFO/олон агуулах.

## I. Платформ ба API

| ID | Шийдвэр |
|---|---|
| D-I1 | REST JSON API (OData биш). Keyset pagination, `Idempotency-Key` header (POST), `ETag`/`If-Match`. Үйлдлүүд нь `POST /sales-invoices/{id}:post` хэлбэртэй. |
| D-I2 | Эрх: BC-ийн загвараар permission set → object/action (R/I/M/D/X). Анхдагч role: Owner, Accountant, Sales clerk, Viewer, External accountant. |
