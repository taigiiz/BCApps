# ADR-0013: Монголд байршуулах ба PosAPI operator загвар

- **Төлөв:** Батлагдсан (Accepted)
- **Огноо:** 2026-10-06
- **Шийдвэр гаргагч:** Архитектурын баг, бүтээгдэхүүний эзэн
- **Холбогдох:** [02-architecture.md](../02-architecture.md) §9.3, §12. [ADR-0012](./ADR-0012-outbox-idempotency-ebarimt.md), [ADR-0022](./ADR-0022-backups-pitr-archive-retention.md), [ADR-0023](./ADR-0023-compliance-gates.md)

## Нөхцөл байдал

- **PosAPI 3.0-ийн хязгаарлалт:**
  - local REST үйлчилгээ (`:7080`, токенгүй);
  - **зөвхөн дотоод сүлжээнд, зөвхөн Монголын IP-ээс** хандана;
  - DB ping < 100 ms;
  - нэг instance-д ≤ 1 000 мерчант, ≤ 100 000 баримт/өдөр ([mn-integrations-market.md](../research/mn-integrations-market.md) §2.5).
- **ETAX API** мөн зөвхөн Монголын IP-ээс хандана.
- **Operator загвар.** Operator нь мерчантыг `saveOprMerchants`-ээр бүртгэнэ. Мерчант өөрөө баталгаажуулна.
- **Хувь хүний мэдээлэл.** Хувь хүний мэдээлэл хамгаалах хууль гадаад руу дамжуулахыг зөвхөн хууль, гэрээ эсвэл зөвшөөрлөөр зөвшөөрдөг (art. 14.1). Ерөнхий data localisation-ий шаардлага UNVERIFIED.
- **Хоёр хэсэгт хуваах эрсдэл.** ERP-г гадаадад, PosAPI gateway-г Монголд байрлуулбал VPN, хоцрогдол, алдааны горим нэмэгдэнэ. Синхрон POS хэвлэлт хил дамнасан холболтоос хамаарна.

## Шийдвэр

1. **Production-ий бүх бүрэлдэхүүн Монголд байна.** Үүнд:
   - app, worker, PostgreSQL, object storage;
   - PosAPI;
   - observability, нөөц хуулбар;
   - SMTP relay.

   Хоёр байршил: ДЦ-1 (үндсэн), ДЦ-2 (нөөц), хоёулаа Монголд.
2. **Бид PosAPI operator болно.** PosAPI instance-ууд манай ДЦ-ийн **`ebarimt` VLAN**-д ажиллана.
   - Ирэх урсгал: зөвхөн app VLAN-аас `:7080` руу.
   - Гарах урсгал: зөвхөн `api.ebarimt.mn` (103.17.108.216/217), `auth.itc.gov.mn` (103.87.69.75/76) ба NTP.
   - app VLAN-ийн гарах урсгал мөн allow-list-тэй: ITC (`api.ebarimt.mn`, `auth.itc.gov.mn`, `service.itc.gov.mn`), `www.mongolbank.mn`, SMTP relay, NTP ([02-architecture.md](../02-architecture.md) §9.3).
3. **Мерчант = компани (ТТД).**
   - Instance-ийг дүүргэхдээ ≤ 800 мерчант (80%) ба ≤ 70 000 баримт/өдөр хүртэл ачаална.
   - Хуваарилалт тогтвортой (sticky). Ачаалал ихтэй POS мерчантуудыг instance-уудад тэнцүү тараана.
   - Хүрээ: 1 000 тенантад 2 + 1, 5 000 тенантад 7 + 1 instance.
4. **Мерчант бүртгэх урсгал:** `DRAFT → REQUESTED (saveOprMerchants) → AWAITING_CONFIRMATION → ACTIVE (/rest/info-д харагдсан) → SUSPENDED`.
5. **PosAPI-ийн ажиллагаа:**
   - `sendData`-г 4 цаг тутам дуудна;
   - `/rest/info`-г 5 мин тутам шалгана;
   - alert: `leftLotteries < 100`, сүүлийн илгээлт > 12 цаг;
   - VM-ийн snapshot цаг тутам авна;
   - бүх host NTP-ээр синк хийгдэнэ.
6. **Staging.** Тусдаа PosAPI ITC-ийн staging-тэй холбогдоно. Staging дээр ачааллын тест хийхгүй. Ачааллын тестийг stub PosAPI-гаар хийнэ.
7. **Deploy.** Self-hosted GitHub runner ба хувийн image registry ДЦ дотор байна.
8. **Провайдер.** Хоёр байршил, private VLAN, S3-тэй нийцтэй storage (байхгүй бол SeaweedFS), VM-ийн SLA ≥ 99.9% санал болгосон Монголын провайдерыг сонгоно. Нэр ба үнэ UNVERIFIED. Үнийн санал авна.
9. **Нөөц хуулбар Монголоос гарахгүй.** Гадаадын CDN, фонт, SaaS-ийн лог үйлчилгээ ашиглахгүй.

## Үр дагавар

**Эерэг:**
- PosAPI-ийн техникийн шаардлагыг шууд хангана.
- Хил дамнасан өгөгдөл дамжуулахгүй.
- Синхрон POS хэвлэлт найдвартай.
- Operator загвараар тенант бүрт локал програм суулгах шаардлагагүй.

**Сөрөг ба эрсдэл:**
- **Монголын провайдерын managed үйлчилгээ хязгаарлагдмал** (UNVERIFIED). Бид DB, HA ба storage-ийг өөрсдөө ажиллуулах магадлалтай. Энэ нь DevOps-ийн ачааллыг нэмнэ.
- **PosAPI-ийн local төлөв** алдагдаж болно: илгээгдээгүй баримт.
  - Бууруулах арга: 4 цаг тутмын `sendData` ба цаг тутмын snapshot. Эрсдэлийг ITC-тэй тодруулна.
- **Operator болох журам** (гэрээ, шаардлага, зардал) ба мерчантыг instance хооронд шилжүүлэх журам UNVERIFIED.
- **Гадаадад бүс сонгох боломжгүй** тул байгалийн гамшиг ба сүлжээний бүсийн эрсдэлийг Монголын 2 байршлаар л бууруулна.

## Харьцуулсан хувилбарууд

| Хувилбар | Давуу тал | Сул тал | Яагаад сонгоогүй |
|---|---|---|---|
| Гадаад cloud + Монголд PosAPI gateway (VPN) | Managed үйлчилгээ баялаг | Хил дамнасан PII. VPN-ийн хоцрогдол ба алдаа. Хоёр байршлын үйл ажиллагаа | Нийцэл ба энгийн байдал |
| Тенант бүрийн байранд PosAPI agent (on-prem) | Operator болох шаардлагагүй | Мянга мянган суулгалт, дэмжлэг. Бичил бизнест сервер байхгүй | Үйл ажиллагаа хэт хүнд |
| QPay-ээр eBarimt гаргах | PosAPI ажиллуулах шаардлагагүй | Бүх борлуулалт QPay-ээр явахгүй. Нэхэмжлэх ба бэлэн мөнгө хамрагдахгүй | Хамрах хүрээ. QPay-ийг v2-д сонголт болгоно |
| Нэг том PosAPI | Энгийн | ≤ 1 000 мерчантын хязгаар | Журам |
