## 2. Нэгтгэсэн нээлттэй асуулт

### 2.1 Нэгтгэсэн арга

- Эх сурвалжаас **391** асуулт цуглуулав. Үүнээс 10 нь эх баримтдаа аль хэдийн "Шийдэгдсэн" эсвэл зурсан байсан. Үлдсэн 381-ээс 53 судалгааны асуулт DECISIONS эсвэл модулийн spec-ээр хаагдсан (§2.8). Бусдыг давхардлаар нь нэгтгэж **96** нээлттэй асуулт болгов (§2.3–2.7). Тоо: Хавсралт А.

- Модулийн spec-ийн асуултын ID-г (OQ-PST-01, OQ-TAX-04, 12 OQ-05, 13 Q7 г.м.) өөрчлөхгүй. Энэ баримтын ID (TX-01 г.м.) тэдгээрийг бүлэглэнэ.

### 3.1 Хэрхэн гаргав

[research/legal-parameters.md](./research/legal-parameters.md)-ийн `status = unverified` мөрүүд. Seed-ийг шинэ DB-д ачаалж (`db/apply.sh ... --seed --test`) дараах query-гээр тулгав: **38 мөр, 37 `param_code`** (`min_wage.hourly` 2 мөртэй). Итгэл: `low` 13, `medium` 25.

```sql
SELECT param_code,
       coalesce(value_numeric::text, value_text) AS value,
       unit, effective_from, effective_to, confidence
FROM tax.tax_parameter
WHERE status = 'unverified'
ORDER BY param_code, effective_from;
```

**Дүрэм** ([08](./08-tax-vat-mn.md) BR-TAX-12): `unverified` мөр ledger-т бичигдэх дүнд (`ParameterUse.Posting`) орохгүй, зөвхөн анхааруулга, тайлан, хуанлид (⚠ тэмдэгтэй) орно. Тиймээс доорх мөрүүд R1-ийн posting-ийг шууд эвдэхгүй. Гэхдээ хэрэглэгчид буруу сануулга, буруу хугацаа харуулах эрсдэлтэй (R-01).

**"Батлах хугацаа"**: **R1** = пилот эсвэл GA-аас өмнө (R1-ийн хуанли, анхааруулга, wizard, эхний үлдэгдэл, пилотын компани сонголтод нөлөөлнө); **R2** = тухайн R2 функц (цалингийн журнал, ҮХ, ААНОАТ-ын туслах тайлан, хялбаршуулсан НӨАТ) гарахаас өмнө.
